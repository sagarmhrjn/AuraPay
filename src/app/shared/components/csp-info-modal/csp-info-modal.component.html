Defense-in-Depth for Merchant Payments (NRB & PCI Compliance)

In a merchant payments portal, client-side security is top priority. Sensitive PII (Citizenship numbers, PANs) and banking credentials (NCHL clearing & account numbers) are targets for Magecart, form-jacking, and XSS attacks. Content Security Policy (CSP) restricts executable script origins, prevents malicious exfiltration, and enforces Nepal Rastra Bank (NRB) Payment Systems Directives and PCI-DSS v4.0 requirements.

code Recommended HTTP Response Header Directives
Directive Value Mitigation Target
default-src 'self' Fallback policy blocks unauthorized remote assets
script-src 'self' 'nonce-$request_id' Neutralizes DOM/Stored XSS injection; rejects unsafe-eval
style-src 'self' https://fonts.googleapis.com Allows local and trusted stylesheets
font-src 'self' https://fonts.gstatic.com data: Restricts web font sources to local and verified hosts
connect-src 'self' https://api.payments.np wss: Prevents credential and PII data exfiltration to external origins
frame-ancestors 'none' Eliminates Clickjacking and iframe UI redressing attacks
form-action 'self' Guarantees forms and auth tokens cannot POST to foreign sites
base-uri 'self' Prevents HTML <base> tag hijacking for relative links
terminal Production Reverse Proxy / Edge Header Configuration 
# Nginx or Cloudflare Edge Response Header
add_header Content-Security-Policy "
  default-src 'self';
  script-src 'self' 'nonce-$request_id';
  style-src 'self' 'unsafe-inline' https://fonts.googleapis.com;
  font-src 'self' https://fonts.gstatic.com data:;
  img-src 'self' data: https://images.unsplash.com;
  connect-src 'self' https://api.aurapay.np wss://*.aurapay.np;
  frame-ancestors 'none';
  form-action 'self';
  base-uri 'self';
  report-uri https://telemetry.aurapay.np/csp-reports;
" always;
